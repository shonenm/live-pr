# ロードマップ (2026-11)

## この文書の位置づけ

[戦略](strategy.md) は「何を、なぜ作るか」を決める。この文書は「どの順で、
どのリリースに入れるか」を決める。両者が食い違ったら戦略を正とし、この文書を
直す。

日付は置かない。各段階は「次へ進む条件」で区切る。

## リリースの系統

| 系統 | ブランチ | 中身 | 状態 |
| --- | --- | --- | --- |
| 1.x | `release/1.x` | ローカルの PR viewer と意思決定タイムライン。修正のみ | v1.0.0 公開済み |
| 2.0 | `main` | 戦略の 6 つの柱。互換性を壊しうる | v2.0.0-alpha.1 公開済み |

- 1.x に機能は足さない。不具合の修正だけを `release/1.x` に入れ、パッチ
  として出す。
- 修正は main に先に入れ、1.x にも該当する場合に `release/1.x` へ取り込む。
- 2.0.0 を出した時点で 1.x の修正を終える。

## 2.0 の段階

| 段階 | タグ | 入れるもの | 次へ進む条件 |
| --- | --- | --- | --- |
| alpha | `v2.0.0-alpha.N` | 柱の機能。壊す変更もここで入れる | 2.0 に入れる柱が揃い、壊す変更が出尽くした |
| beta | `v2.0.0-beta.N` | 修正と公開ドキュメントの書き直し。壊す変更は入れない | 下の「2.0.0 の条件」をすべて満たした |
| 安定版 | `v2.0.0` | — | — |

プレリリースは Homebrew に流れない。安定版の利用者は 2.0.0 まで 1.x を使う。

## alpha で進める順番

柱の番号は戦略のものである。順番は提案で、着手前に見直してよい。

### A1. 柱 2 を実運用に載せる

alpha.1 で実行、署名、検証、TUI の表示までが入った。実際にリモートの job が
省略されることは、まだ確かめていない。

1. このリポジトリに署名者を登録し、証跡つきで `test` job がスキップされる
   ことを確かめる。ssh-agent と Secure Enclave の鍵でも確かめる。
2. マージゲート。TUI の `m` で、証跡のない変更のマージを止める。
3. 複数の worktree から同時に実行したときの待ち行列。

進む条件: このリポジトリの PR が、日常的にローカルの証跡でリモートの job を
省略している。

### A2. 計測の仕組み（柱 5）

戦略の目標値（表示まで 100 ms、状態とキャッシュで 10 MB）は暫定で、測る手段が
ない。機能を足す前に測れるようにし、以降の柱が目標を割っていないかを確かめ
られるようにする。

1. 起動から最初の表示までの時間と、ディスク上の容量を出すコマンドまたは
   ベンチマーク。
2. 計測して目標を超えた箇所だけを直す。増分取得はここで要否を判断する。

進む条件: 2 つの指標が再現可能な手順で測れ、目標値を見直し済みである。

### A3. CI の進捗とログ（柱 2 の続き）

1. step 単位の進捗とログ。出力のストリーム化、ログの保存、ログを読むペイン、
   `::group::` の解釈。
2. strict モード。検証に失敗したとき、フォールバックせず job を失敗させる。
3. GitHub Actions 以外の検証 job の雛形。最初の候補は Woodpecker。

進む条件: 失敗したチェックの原因を、TUI から離れずに特定できる。

### A4. agent との対話（柱 3）

1. 設計を戦略に書き足す。@mention の宛先、裏で実行する手段、回答の返し方、
   作業中のセッションとの分離。
2. @mention つきのコメントで指示を出し、回答がコメントとして返る。
3. 行コメントを使ったやり取り。

進む条件: PR 上の指摘から修正までを、agent のセッションに切り替えずに
回せる。

### A5. ローカルならではの見せ方（柱 1）

1. 設計を戦略に書き足す。まとめる単位（タスク、worker）を何から得るか。
2. PR 一覧のタスク単位と worker 単位のまとめ。
3. PR の説明の拡張。

A5 は表現の単位が未決定で、A4 の結果（agent と PR の対応づけ）に依存する
見込みが高い。そのため最後に置く。2.0.0 に入れず 2.1 に回す候補である。

### 柱 4 と柱 6

LOCAL / LIVE / REMOTE と意思決定タイムラインは実装済みで、2.0 では維持する。
新しい作業は予定していない。

## 2.0 で壊す変更

メジャーを上げる機会にまとめて入れる。確定したものだけをここに書き、入れた
時点でリリースノートに移行手順を書く。

| 変更 | 状態 |
| --- | --- |
| モジュールパスを `github.com/shonenm/live-pr/v2` にする | alpha.1 で実施済み |
| `.live-pr/` を gitignore の対象から外し、検証スクリプトと署名者の置き場にする | alpha.1 で実施済み |
| 移行用に残してある旧設定の読み込み（トップレベルの `reviewer`、旧パス）を削除する | 候補。未決定 |

## 2.0.0 の条件

- A1 から A4 が「進む条件」を満たしている。A5 を含めるかは A4 の後に決める。
- 壊す変更がすべて入り、1.x からの移行手順がリリースノートにある。
- README と prior-art が新しい方針で書き直されている。
- 2 つの性能指標が目標値の内側にある。
- beta を自分の日常の開発で使い、1.x に戻る理由が残っていない。

## 1.x と共通の既知の課題

main で直し、1.x にも該当するものは `release/1.x` に取り込む。

- 開いていない view のタブ件数が、古いキャッシュのまま表示される。
- 全角文字を含む行が毎フレーム再描画される（upstream の ultraviolet の挙動）。
- 端末の高さが足りないと、ヘルプのポップアップが切れる。
